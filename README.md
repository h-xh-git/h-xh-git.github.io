# 夜坐所安的小屋

一个纯静态的个人博客：**没有后端、没有数据库、没有构建步骤**，双击 `index.html` 就能看。

- **线上地址**：<https://h-xh-git.github.io/> —— 仓库 `h-xh-git/h-xh-git.github.io`，GitHub Pages 从 `main` 分支根目录发布（见「部署」一节）。
- **形态**：手写 HTML / CSS / 原生 JS，零依赖、零构建；页面里全是**相对路径**，换目录、换域名都不会失效。
- **内容怎么存**：五个栏目的数据都在 `assets/data/*.js`，页面只负责渲染 —— 改内容 = 改那几个文件。
- **下一步**：改写成「前端 + 服务端」的完整博客，见文末「路线图：服务器版」。

## 往哪放东西

**图片放哪** —— `assets/img/` 下面一个用途一个文件夹（2026-10-09 整理过一次）：

| 文件夹 | 放什么 | 谁在读 |
| --- | --- | --- |
| `profile/` | 站点头像 | `index.html` 的 Hero 头像 |
| `home/` | 首页照片卡的图 | `index.html` 的照片卡 |
| `projects/` | 项目封面 | `assets/data/projects.js` 的 `cover` |
| `essays/` | 随笔配图（文件名跟 `slug` 对齐） | `assets/data/essays.js` 的 `image` |
| `album/flower` `.journey` `.bird` `.people` | 相册照片，按四个分类分开放 | `assets/data/album.js` 的 `src` |
| `friends/` | 友链头像 | `assets/data/friends.js` 的 `avatar` |
| `trail/` | 足迹照片 | `assets/data/collections.js` 的 `image` |
| `originals/` | 原始大图留底 | 页面不直接读 |

**相册照片** → 照片按分类放进 `assets/img/album/` 下的四个子文件夹，再到 `assets/data/album.js` 里加一条

- 加一条要填：`src`（路径，从站点根目录写起，例如 `assets/img/album/flower/2026-10-shuilian.jpg`）、`title`（标题）。
- 选填：`kind`（分类）、`place`（信息条上的小字）、`date`（`YYYY-MM-DD`，相册按它倒序排）、`w` / `h`（图片像素宽高）。
- 分类 `kind` 的取值范围在 `assets/data/album.js` 顶部的 `ALBUM_KINDS` 里（现在是 花枝入梦来 / 悠悠行旅中 / 飞鸟倦归林 / 漫漫人物录）—— 改标签文字、加分类都在那儿，页面上那排分类标签会自己跟着变。没填、或填了表里没有的值会归到「其他」，不会让照片从墙上消失。
- `w` / `h` 建议填：瀑布流靠它算每张卡片的高度，不填就按 3:2 估 —— 页面不会坏，只是排出来松紧不匀。这两个数直接抄文件属性里的宽高就行，不用自己算比例。
- 长边建议不超过 1600px。手机拍的原图动辄 4000px、好几 MB，直接放也能显示，但页面会变重。
- 原始大图可以丢进 `assets/img/originals/` 留底，网页用的压缩版我从原图生成，你不用自己压；顺手把 `w` / `h` 也一起填了。

**足迹照片** → `assets/img/trail/`（单独一个文件夹，跟相册分开）

- 放好告诉我哪张对应哪次出行，我把路径写进 `assets/data/collections.js` 的 `image` 字段。
- 没配照片的足迹条目只显示文字，时间轴照常连下去。

**随笔正文** → `assets/data/essays.js`（不用自己写 HTML）

- 把文字发我，我排进去；想自己动手就照里面的注释加一个对象：标题、日期、摘要、`body` 数组（字符串是一段，`{ h: "…" }` 是小标题，`{ quote: "…" }` 是引用块）。
- **随笔配图** → `assets/img/essays/`（文件名跟 `slug` 对齐，例如 `flower-words.jpg`）。网页版**长边压到 1600px** 就够（正文栏最宽 36em ≈ 610px，首页卡上那张小图是 16:9 裁切）；原始大图丢 `assets/img/originals/` 留底。不填 `image` 就只显示文字，目录页那一行照样排。
- 配图出现在两处：首页「最近写下的」卡左边的缩略图（16:9 裁切）、单篇阅读页**右侧**的整幅（不裁切）。
- **单篇阅读页在宽屏（≥901px）是左文右图**：正文在左，照片在右、跟正文顶端对齐，往下读的时候照片贴着右边跟着走（`sticky`）；窄屏自动变回竖排，照片落到正文下面。没有配图的篇目（比如「夜里坐着」）不受影响，还是单栏。
- 加进去之后，首页「最近写下的」卡、「随笔」目录页、单篇阅读页三处一起更新，不用改别的。
- **现在 4 篇**：《花语》（`flower-words`，正文 413 字，配图是 2025-05-12 拍的月季）是你给的原文；另外 3 篇（海边的一个下午 / 三角梅开了 / 夜里坐着）是占位示例 —— 标题和摘要沿用早期版本的原话，正文是我为了页面完整重写的，日期按同一批照片推的。
- ⚠️ **日期填的是「这篇写的是哪一天」**：《花语》写的是 2025-05-12 那天在公园拍花，所以 `date` 是 2025-05-12 —— 它在目录里排最后，也**不会**出现在首页「最近写下的」卡（那张卡只取最近 3 篇）。想让它排前面、上首页，把这个 `date` 改成写作当天（例如 2026-10-09）就行，一处改完三处都跟着动。

**项目** → `assets/data/projects.js`

- 加一个：在 `PROJECTS` 里补一个对象。`title`（项目名）必填，其余都选填：`summary`（一句话）、`status`（在做 / 已完成…）、`date`（`YYYY-MM-DD`，只用来排序和显示成 `2026.09`）、`cover`（封面图，路径从站点根目录写起）、`link`（外链，填了整张卡可点、右上角才出现箭头）。
- 不填封面就用「大号标题 + 右上 ✳」的占位块，不用先准备图；不填外链的卡不可点。
- 只剩一个项目时，卡片会自己变成**左图右文**的横排（大标题 + 撑满高度的封面），不用改 HTML。

**友链** → `assets/data/friends.js`

- 加一位：在 `FRIENDS` 里补一个对象。`name`（网站名 / 朋友称呼）必填，其余选填：`url`（站点地址，填了整张卡可点、右上角才出现箭头）、`intro`（一句话）、`avatar`（头像图，路径从站点根目录写起）、`sign`（分隔线下面那行小字，不填就显示网址的域名）。
- 头像不填也行：会自动用名称的第一个字，配三种柔和底色按顺序轮换。
- 想换头像底色/圆角/卡片尺寸，都在 `assets/css/page.css` 第 11 节；列数不用管，自适应。

**音乐** → `assets/music/playlist.js`（音频本身**不在仓库里**）

- 现状：13 首 mp3 只在本地，`.gitignore` 里排除了。所以线上播放器会「一首接一首打不开」，最后平静地显示一句「音乐暂时没上线」；本地双击照常能播。
- 歌单里每条有两种写法（解析在 `player.js` 的 `trackSrc()`）：
  - 只写文件名 `夜空中最亮的星-逃跑计划.mp3` → 自动去 `assets/music/` 取；
  - 直接写完整地址 `https://…/x.mp3`（或 `//…`、`/music/x.mp3` 这类带斜杠的路径）→ **原样使用** —— 这就是以后换托管时唯一要改的地方。
- 数组顺序 = 播放器列表顺序；显示名 = 取地址最后一段、再去掉扩展名。
- 那 116 MB 商业歌曲将来放哪，见「音乐以后放哪」。

## 本地预览

- **直接双击 `index.html`（推荐）**：所有路径都是相对的，换文件夹、换盘符、整份拷到别处都不会失效；音乐卡在这种情况下能正常播放和拖进度条。
- 想用本地服务器看：在站点根目录执行

  ```
  python -m http.server 8899 --bind 127.0.0.1
  ```

  然后浏览器打开 `http://127.0.0.1:8899`。

  ⚠️ 这类简易静态服务器（包括 `python -m http.server`）不支持 HTTP Range 请求，实测音频只返回 200 全量、没有 `Accept-Ranges`，浏览器拿不到可跳转区间——**表现就是音乐能播、但进度条拖不动**。要拖进度就用上面双击的方式，或换一个支持 Range 的服务器。

## 部署（GitHub Pages）

线上是 GitHub Pages 的**用户站**：仓库 `h-xh-git/h-xh-git.github.io`、分支 `main`、根目录发布，网址 <https://h-xh-git.github.io/>。根目录那个空文件 `.nojekyll` 只是告诉 Pages 别走 Jekyll，**别删**。

改完内容推上去：

```
cd D:\boke_demo\yezuo-blog
git add -A
git commit -m "更新了什么"
git push
```

推完一两分钟 Pages 会重建，刷新线上地址看效果；构建状态在仓库的 **Actions** 页（workflow `pages-build-deployment`）。

**什么在仓库里、什么不在**（`.gitignore`）：

| 不在仓库里 | 为什么 | 线上会怎样 |
| --- | --- | --- |
| `assets/music/*.mp3` | 13 首商业歌曲共 116 MB，暂时不带 | 播放器自动降级，一句「音乐暂时没上线」 |
| `assets/img/originals/` | 原图留底，页面不读（约 7 MB） | 无影响（页面用的是压缩后的副本） |
| `*说明.txt`、`_dev/`、`_tmp*`、`*.bak` | 本地草稿与占位说明 | 无影响 |

> 还有一层原因：免费账号的 Pages 只能从**公开仓库**发布，站点仓库本身藏不住东西 —— 要「仓库里看不到 mp3」，只能在音频来源那一层做。

## 音乐以后放哪

静态站要出声，音频就必须是「陌生人也能下载」的东西。私人库不行：匿名请求拿到的是 404，把 token 写进页面又等于公开；`base64` 内嵌同理（明文，还多占三分之一直体积）。

| 方案 | 音频放哪 | 站点仓库 | 挡不住什么 |
| --- | --- | --- | --- |
| 对象存储 + 防盗链 | R2 / 七牛 / 腾讯云 COS，配 Referer 白名单只允许 `h-xh-git.github.io` | 8 MB | 拿到直链的人仍能下载 |
| Release 附件 | 站点仓库的 Releases | 8 MB（附件不占 git 体积） | 同样公开，站点和音乐绑在一起 |
| 独立公开音乐仓库 | 另开一个公开仓库，用 jsDelivr 或它的 Pages 直链 | 8 MB | 地址公开；好处是隔离，音乐库出事不连累站点 |

定下来之后**只有一处要改**：`assets/music/playlist.js` 里把对应条目写成完整地址。

> 顺带记一笔：把 mp3 解码成 `base64` 再硬编码进页面，实测 122.6 MB 会涨到 163.5 MB、失去流式播放，而且完全没改变公开性，所以不走这条路。想要界面上的波形 / 律动条，可以把解码出的峰值数据（13 首合计数十 KB）硬编码进去，那是另一回事。

**音乐播放器（首页大卡 + 全站迷你条）**

- 音量和你上次听到第几首会记在浏览器本地（`localStorage`）；某些情况下浏览器会禁用本地存储，播放器会自动降级，不影响播放。

**为什么原来一换页音乐就断，现在怎么接上的**

每个页面是一个独立文档，换页时旧文档连 `<audio>` 一起销毁 —— 所以只在首页放播放器的话，一点导航就静音。现在播放器是全站的：

- `assets/js/player.js` 在**七个页面都加载**（`assets/music/playlist.js` 排在它前面）。它不用写死路径，而是从自己脚本的 URL 反推站点根目录，所以在 `projects/` 这种子目录里也能找对 `assets/music/`。
- 首页有 `.music-card` 时就用那张大卡；**其他页面没有大卡，它就自己造一条右下角的迷你条 `.music-bar`**（播放 / 暂停、歌名、细进度条、上一首 / 下一首、✕）。迷你条**只在「这一会儿确实在放歌」时才出现**，没在放歌的页面完全看不到它。
- 换页前把「第几首 + 播到几秒 + 是否在放」写进 `sessionStorage`（另外往 `localStorage` 和 `window.name` 各写一份当退路，`pagehide` / `beforeunload` / 每 2 秒一次都写）；下一页读回来：先按秒数把进度 seek 回去，再试着接着播。
- 浏览器可能拦下自动播放（`NotAllowedError`，需要用户手势）。这时迷你条进入 `is-pending`：标题变成「点一下继续 · 歌名」、播放键脉动，然后**点页面上任何地方**都会接上（`pointerdown` / `keydown` 各挂一次）。浏览器放行时则完全无缝。
- 30 秒没动静的会话不再自动续播（`FRESH_MS = 30000`）—— 关了标签页过半天再打开，不会突然出声。
- 点迷你条上的 ✕：暂停 + 清掉会话 + 在当前标签页记一个 `yezuo-player-off`，之后翻页也不再冒出来；重新按播放就会把这个记录清掉。
- 只有启用过播放器的页面才会写会话（首页大卡算启用）—— 否则扫一遍栏目页也会把刚存的进度覆盖成 0。
- 加歌只需要两步：mp3 放进 `assets/music/`，文件名补进 `assets/music/playlist.js`（文件名要完全一致，含扩展名；顺序就是列表顺序）。

**几个刻意的设计：**

- **giscus 的脚本是「第一次点开按钮」时才注入的**（`mountComments()`），没点过的访客完全不碰这个第三方脚本 —— 别改成页面加载时就 `<script src="https://giscus.app/client.js">`，那样每个访客都会被请求 giscus。
- **在 `file://` 下（双击 index.html 预览）弹窗里不会出评论区**，只显示一句说明。这是 giscus 的性质：它要站点在 http(s) 上才连得上 GitHub，不是本地能改的。判断写在 `review.js` 的 `location.protocol === "file:"` 那一支。
- 关闭有三条路：右上角 ✕、点背景、按 ESC；打开时 `<body>` 会加 `.review-open` 锁住底下滚动，关掉时焦点回到那颗按钮；Tab 被锁在弹窗里（`keydown` 里那段）。CSS 在 `components.css` 的「访问与评价弹窗」一节，**`.review-modal[hidden] { display: none }` 这条不能删** —— `display: flex` 会盖掉浏览器默认的 `[hidden]`。
- 弹窗只放在首页。想让它出现在别的页面（比如每篇随笔下面、或页脚加一个入口），说一声 —— 页面里加一份同样的弹窗 DOM + 引 `review.js` 就行。

## 路线图：服务器版（前后端完整开发）
